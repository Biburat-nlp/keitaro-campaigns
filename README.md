# Keitaro Campaigns

Инструмент для работы с кампаниями трекера Keitaro через Admin API:

1. **Создание кампании.** На входе название, одна или несколько стран (ISO-коды) и ID оффера. На выходе кампания с доменом, группой и источником и двумя потоками:
   - «Geo AU, NZ» — обычный поток (`type: regular`) с фильтром по выбранным странам, делает редирект на `https://google.com`;
   - «Offers» — запасной поток (`type: default`, `schema: landings`), отправляет всех остальных на выбранный оффер (100%).
2. **Редактор кампании.** Потоки загружаются из Keitaro в нашу базу, офферы добавляются, удаляются и возвращаются в черновике, доли можно закреплять, а изменения попадают в Keitaro только по кнопке «Опубликовать в Keitaro». Ещё можно переименовать кампанию и править страны гео-фильтра.

Стек: FastAPI + SQLAlchemy (SQLite) на бэкенде, React + TypeScript (Vite) на фронтенде.

Интерфейс на русском и английском: переключатель RU / EN в правом верхнем углу.

## Быстрый старт

### Что нужно заранее

- **Python 3.11+**. Проверка: `python --version`; на Windows `py --version`.
- **Node.js 20.19+ или 22.12+** (этого требует Vite 8). Проверка: `node --version`.

Нужны два терминала: в одном работает бэкенд, в другом фронтенд. Все команды ниже выполняются из корня репозитория.

### 1. Бэкенд

**Windows (PowerShell):**

```powershell
cd backend
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

**Linux / macOS:**

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
nano .env
.venv/bin/python -m uvicorn app.main:app --port 8000
```

В файле `.env` замените `your-api-key` на свой ключ, остальное можно не трогать. Готовность бэкенда видна по строке `Uvicorn running on http://127.0.0.1:8000`. Проверка: http://127.0.0.1:8000/api/health должен ответить `{"status":"ok"}`. Документация API (Swagger): http://127.0.0.1:8000/docs.

База SQLite (`backend/keitaro.db`) создаётся сама при первом запуске.

### 2. Фронтенд

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Dev-сервер Vite проксирует запросы `/api` на бэкенд `http://127.0.0.1:8000`.

### 3. Тесты и проверки

```powershell
cd backend
.venv\Scripts\python -m pytest
```

```bash
cd backend
.venv/bin/python -m pytest
```

Тесты бэкенда не ходят в настоящий Keitaro: вместо него используется фейковый стенд на `httpx.MockTransport`, так что ключ для них не нужен.

Фронтенд: `npm run build` (проверка типов и сборка) и `npm run lint` в папке `frontend`.

### Если что-то не запускается

| Симптом | Что сделать |
|---|---|
| `python` не найден (Windows) | Используйте `py`, как в командах выше. |
| Порт 8000 занят | Запустите бэкенд на другом порту, например `--port 8001`, а фронтенд — с адресом бэкенда: PowerShell `$env:BACKEND_URL="http://127.0.0.1:8001"; npm run dev`, bash `BACKEND_URL=http://127.0.0.1:8001 npm run dev`. |
| Порт 5173 занят | `npm run dev -- --port 5174`. |
| В интерфейсе «Бэкенд недоступен» | Бэкенд не запущен или запущен на другом порту, см. строку про порт 8000. |
| «Keitaro отклонил API-ключ» | В `backend/.env` неверный `KEITARO_API_KEY`. После правки `.env` перезапустите бэкенд. |
| `npm ci` ругается на версию Node | Обновите Node.js до 20.19+ или 22.12+. |

### API бэкенда

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/catalog` | домены, группы, источники, коды стран, значения по умолчанию |
| GET | `/api/offers` | офферы Keitaro |
| GET | `/api/campaigns` | кампании Keitaro и отметка «создана здесь» |
| POST | `/api/campaigns` | создать кампанию `{name, countries, offer_id, domain_id?, group_id?, traffic_source_id?}` |
| GET | `/api/campaigns/{id}` | кампания и её потоки из нашей базы (при первом открытии потоки загружаются из Keitaro) |
| POST | `/api/campaigns/{id}/sync` | «Загрузить из Keitaro»: перечитать потоки и офферы, черновики сохраняются |
| PATCH | `/api/campaigns/{id}` | переименовать кампанию `{name}` |
| DELETE | `/api/campaigns/{id}` | удалить кампанию |
| GET | `/api/campaigns/{id}/operations?offset=0&limit=10` | история изменений, сделанных через инструмент, постранично: `{items, total, offset, limit}`, новые сверху |
| POST | `/api/streams/{id}/countries` | добавить страны в фильтр `{countries: ["NZ", "GB"]}` |
| DELETE | `/api/streams/{id}/countries/{code}` | удалить страну из фильтра |
| POST | `/api/streams/{id}/offers` | черновик: добавить оффер `{offer_id}` |
| POST | `/api/streams/{id}/offers/{offer_id}/remove` | черновик: удалить оффер (уходит в архив) |
| POST | `/api/streams/{id}/offers/{offer_id}/restore` | черновик: вернуть удалённый оффер (Bring Back) |
| PUT | `/api/streams/{id}/offers/{offer_id}/share` | черновик: задать долю вручную `{share}`, доля закрепляется |
| PUT | `/api/streams/{id}/offers/{offer_id}/pin` | закрепить или открепить долю `{pinned}` |
| POST | `/api/streams/{id}/publish` | опубликовать черновик в Keitaro |
| POST | `/api/streams/{id}/cancel` | отменить черновик |

### Редактор офферов (черновик и публикация)

- **Загрузить из Keitaro** (Fetch streams) читает потоки кампании и сохраняет их в нашу базу: таблицы `streams` и `stream_offers`. Потоки без офферов показываются просто как потоки, для гео-потока доступно редактирование стран.
- **Добавить, удалить, вернуть оффер, изменить долю** — всё это меняет только черновик в нашей базе. Поток подсвечивается жёлтым («Есть неопубликованные изменения»), в Keitaro ничего не уходит. Черновик переживает перезагрузку страницы.
- **Опубликовать в Keitaro** отправляет `PUT /streams/{id}` с активными офферами и их долями. Перед публикацией бэкенд перечитывает поток: если его успели изменить в Keitaro после последней загрузки, публикация отклоняется с просьбой сначала загрузить свежие данные. Черновик при этом не теряется. Опубликовать можно, только если есть хотя бы один активный оффер и сумма долей равна 100%.
- **Отменить** возвращает поток к последнему опубликованному состоянию. Офферы, добавленные в черновике, удаляются из базы.
- **Удаление** не стирает оффер, а переводит его в статус `removed`: он серый, доля 0%, рядом кнопка «Вернуть» (Bring Back). Оффер, который ещё не был опубликован, удаляется сразу. Повторное добавление удалённого оффера тоже возвращает его.
- **Удалено в Keitaro.** Если оффер удалили прямо в Keitaro, после «Загрузить из Keitaro» он не пропадает, а становится `removed` с кнопкой «Вернуть», как будто его удалили в нашем редакторе. Доли остальных офферов при этом показываются как в Keitaro, без пересчёта. В истории записывается, какие офферы пропали.
- **Пересчёт долей.** При добавлении, удалении и возврате доли незакреплённых активных офферов делятся поровну на остаток `100% − сумма закреплённых`. Остаток от деления отдаётся первым офферам: 34 / 33 / 33 или, с закреплёнными 25%, 38 / 37 / 25.
- **Закрепление.** Булавка закрепляет текущую долю оффера. Ручной ввод доли тоже закрепляет её. Закреплённые доли не меняются при пересчётах, сумма закреплённых не может превышать 100%. При удалении оффера закрепление снимается. «Отменить» откатывает и закрепления, сделанные в черновике; закрепление на опубликованном потоке без черновика сохраняется.
- **Загрузка при открытом черновике** сохраняет черновик. Строки без правок пользователя (новый оффер, удаление, возврат или закреплённая доля) обновляются из Keitaro, после чего черновик пересчитывается.
- Состояние оффера в потоке Keitaro (`active` / `disabled`) сохраняется при публикации.

### Локализация

- Переключатель RU / EN в правом верхнем углу. Выбор сохраняется в `localStorage`; при первом входе язык берётся из языка браузера.
- Все тексты интерфейса лежат в словаре `frontend/src/i18n.ts`. От языка зависят и названия стран (`Intl.DisplayNames`), и формат дат.
- Фронтенд передаёт язык в заголовке `Accept-Language`, и бэкенд возвращает ошибки на нём же (`backend/app/i18n.py`): бизнес-ошибки, ошибки валидации полей и ошибки обращения к Keitaro. Без заголовка ответы на русском. Текст ошибок, пришедший из самого Keitaro, передаётся как есть.
- Названия потоков, которые создаёт инструмент («Geo AU», «Offers»), не зависят от языка: это данные в Keitaro.

### Страны в гео-потоке

- В Keitaro страны задаются фильтром потока `{"name": "country", "mode": "accept", "payload": ["AU", "NZ"]}`, поэтому у кампании может быть сколько угодно стран.
- В форме создания коды вводятся чипсами: через Enter, запятую или пробел, можно вставить сразу `AU, NZ, GB`. Неизвестные коды не принимаются.
- В редакторе страны добавляются и удаляются у любого потока, где ровно один фильтр `country`. Изменение отправляется как `PUT /streams/{id}` с полным списком `filters`; остальные фильтры потока и режим (`accept`/`reject`) сохраняются.
- Нельзя удалить последнюю страну: фильтр с пустым списком непонятно как поведёт себя в Keitaro.
- Если поток называется так, как его назвал инструмент («Geo AU, NZ»), название обновляется вместе со списком стран. Своё название, заданное вручную, не трогается. Больше пяти стран в названии сокращаются: «Geo AU, NZ, GB, US, CA +2».

### Создание кампании

1. Бэкенд проверяет, что оффер существует (`GET /offers/{id}`), а каждый код страны входит в ISO 3166-1 alpha-2 (плюс `XK`). Коды приводятся к верхнему регистру, дубли убираются.
2. `POST /campaigns`: название, ротация по позиции, домен, группа, источник.
3. Два `POST /streams`: гео-поток и поток с оффером.
4. Если создать поток не удалось, кампания удаляется, чтобы в Keitaro не осталось недособранной кампании.
5. Запись о кампании и операция сохраняются в локальную базу.
